# Scope vectors

The scope grammar shared by delegation (ADR-0017, "Scope vocabulary" and the
`scp` rule) and action approval (ADR-0019, `Action.Resource` and step 6). A
scope is `<ns>:<path>`, `ns` = `[a-z][a-z0-9-]{0,31}`, `path` =
`[a-z0-9][a-z0-9._/-]{0,127}`, compared byte for byte, with no wildcards and no
implication.

- `valid.json`: `scopes` that validate; `Canonical` returns each unchanged.
- `refusals.json`: `cases` of `{scope, why, expect}`; every `expect` is
  `malformed`, and no refused string is normalised into a valid one.
- `lists.json`: `cases` of `{why, input, canonical, verify}`. `canonical` is the
  minter's result (byte-order sort, de-duplicate, 1-32 entries after
  de-duplication), or `null` when the minter refuses. `verify` is the
  verifier's verdict on `input` as given: `ok` only for a list that is already
  canonical, else `malformed`.
- `intersect.json`: `cases` of `{why, sets, result, allowed}`. `result` is the
  sorted, de-duplicated set of valid scopes every set holds; `allowed` maps a
  requested scope to whether every set holds it exactly.

Sorting is by byte (equivalently, ASCII code point) order. Strings are JSON,
so non-ASCII and control bytes in `refusals.json` are escaped.

Generated by `go test ./scope -run TestScopeVectors -update` from the
expectations written in `scope/vectors_test.go`, which are checked against the
code before anything is written; otherwise replayed.
